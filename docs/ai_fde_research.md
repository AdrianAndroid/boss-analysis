# AI / FDE 岗位检索采集调研（2026-11-15）

> 目标：在现有 BOSS 采集链路上，新增「AI/大模型/Agent」与「FDE 前置部署工程师」两类岗位的 JD 采集。本文记录站内检索实测结果、可复用链路、噪声过滤与待办；本期先出方案，确认后再全量采集。

## 1. 结论

- BOSS 站内**关键词检索可直接用 URL 拼接**，无需走 Playwright 骨架：`https://www.zhipin.com/web/geek/jobs?query=<关键词>&city=101010100`（北京）。
- **FDE 在 BOSS 有直接对口岗位**：标题含「FDE 专家 / FDE 豆包前沿部署工程师 / 飞书豆包 FDE / FDE 前线部署工程师 / FDE 前置原型交付工程师 / 前向部署工程师」等；但混入销售、门店、纯运维噪声，需清洗过滤。
- **AI Agent 岗位充足**：标题如「软件开发工程师（AI Agent 方向）/ 大前端 Agent 工程师 / Android 系统 AI Agent / Agent 开发工程师」，与既有 android/agent 样本有重叠。
- 列表卡片选择器、详情提取选择器、`job_key` 去重、断点续采、限速风控**全部可复用**现有链路，只需新增检索组配置与一层噪声过滤。

## 2. 站内检索 URL 规则（实测）

| 项 | 值 |
|---|---|
| 基础地址 | `https://www.zhipin.com/web/geek/jobs` |
| 检索参数 | `query=<URL 编码关键词>`、`city=101010100`（北京） |
| 规范化 | 站点会把 `/web/geek/job` 规范为 `/web/geek/jobs`；中文需 URL 编码 |
| 城市码 | 北京 `101010100`；其他城市后续在配置中补码 |
| 与顶部 tab 关系 | 顶部「推荐/鸿蒙/Android」标签仍在，但列表按 query 过滤；切标签会清 query。新方案直接用 URL query，不点标签 |

## 3. 关键词召回实测（北京，单屏样本）

### 3.1 FDE

召回标题样本：
- FDE 专家、FDE 豆包前沿部署工程师、FDE 专家（Code M）- 飞书项目、飞书豆包 FDE｜前沿部署工程师
- FDE 开发实习生（AI 智能体方向）、FDE（前线部署工程师）、FDE - 大模型前沿部署工程师
- FDE-（AI 智能体 向量库）、前向部署工程师（FDE）

噪声样本（需剔除）：FDE 销售（自带客户资源）、前置广告、运营仓库店长（apple 前置门店店长）、私有化部署运维工程师。

### 3.2 前置部署工程师

召回与 FDE 高度重叠，中文词噪声更多：门店店长、私有化部署运维等。**以英文 `FDE` + 标题语义判定为主，中文「前置/前沿/前线/前向部署」作辅助召回。**

### 3.3 Agent / AI 大模型

- Agent：软件开发工程师（AI Agent 方向）、大前端 Agent 工程师、Android 系统 AI Agent 开发工程师、Agent 开发工程师（AI Agent 出海短剧）、Agent 系统研发工程师、智能研发（Agent 平台方向）。
- AI 大模型：多模态大模型数据质检专家、AI 大模型应用开发工程师、多模态大模型评测专家、AI 医疗大模型训练产品经理。
- 注意：AI 词召回会混入产品经理、标注/质检/训练师等非研发岗，清洗层按规则剔除。

## 4. 链路复用确认

| 环节 | 现状 | AI/FDE 是否复用 |
|---|---|---|
| 列表卡片提取 | `a[href*="job_detail"]`，向上找含 `gongsi` 的卡片容器，文本换行拆字段 | 复用，选择器实测一致 |
| 详情提取 | 标题 `.job-title`/`.name h1`；薪资 `.salary`；JD `.job-sec-text`；公司块 `.sider-company` | 复用，FDE 详情页实测选择器通用 |
| 身份键 `job_key` | 标题编号优先，否则公司+标题+地点+经验哈希 | 复用，全局去重 |
| 去重 | 单批内按 `job_key`；跨期全量保留 | 复用；检索组与既有 1051 岗全局去重 |
| 断点续采 | `progress/checkpoint.json` + 详情待采队列 | 复用 |
| 限速风控 | 串行、≥1.5s 随机抖动、遇验证即停交人工 | 沿用，不并发、不绕过 |

## 5. 接入改动点（待实施）

1. **配置**：`config/search_groups.json` 已建，定义 `ai_agent` / `fde` 两组关键词、保留与剔除规则。
2. **列表采集**：新增按检索组 URL 逐关键词导航 → 滚动/翻页收集卡片 → 落入本期 `list_merged`，`groups` 字段标注命中组。
3. **详情采集**：复用现有详情队列与提取逻辑；新检索岗位与既有记录按 `job_key` 合并留痕。
4. **清洗过滤**：按各组 `drop_rules` 剔除非研发岗，记录剔除原因；原始底稿不删。
5. **分析与报告**：报告新增检索组覆盖表；区分"关键词召回量"与"清洗后有效岗位量"；FDE 样本偏小，按方向性结论处理。
6. **词典**：`config/skills_dict.json` 视需要补 FDE / RAG / 向量库 / 智能体工作流等词。

## 6. 风控红线（沿用 SPEC 第 4 节）

- 单浏览器串行访问，详情间隔 ≥1.5s 带随机抖动；不并发。
- 遇登录/滑块/人机验证立即停止，交人工接管，不绕过、不重试绕检。
- 不读取/导出 cookie、token、localStorage、会话存储；`auth/` 禁止入库。
- 只读采集，不投递、不打招呼、不改账号状态；内容仅用于个人岗位分析。
