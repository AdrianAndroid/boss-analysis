移动端开发 → AI Agent / 大模型应用开发 转型路线

口径：需求数据来自本仓库 reports/2026-11-18/ 北京 242 个 AI/Agent 岗位 JD 的实测抽取（覆盖率 = 命中该技能的岗位数）。 现状判定基于移动端开发背景（C++ / Rust / Kotlin / Flutter / Swift / 鸿蒙）。 本文档目标：明确缺口、给出分阶段可实操路径与两个可落地项目，作为求职技能补齐的执行清单。

一、目标岗位定位

  • 目标方向：AI Agent / 大模型应用开发工程师（偏应用工程落地，不是算法模型训练岗）。
  • 典型工作内容：接 LLM API、搭建 RAG 知识库、实现工具调用与多步 Agent、把智能体封装成可部署的后端服务。
  • 不要求：从零训练/预训练大模型、推导 Transformer 数学、发论文；但需要懂模型能力边界、上下文窗口、Token 成本、延迟与稳定性。

五、分阶段实操路线

阶段 1：Python + LLM 调用 + Prompt（约 2–3 周）

目标：能用 Python 调通大模型接口，写出可控、可解析的提示词。

学习项 - Python：虚拟环境（venv / uv）、依赖管理、类型注解、asyncio 基础、requests/httpx、JSON 处理、错误与重试。 - LLM 接口范式：messages 结构（system / user / assistant）、参数（temperature、max_tokens、top_p）、流式 stream、Token 与上下文窗口、模型档位与成本。 - Prompt 工程：角色与目标、约束与边界、输出格式（JSON / Markdown）、Few-shot 示例、让模型自我校验、解析失败兜底。

动手实验 1. 写一个命令行脚本，接入一家厂商的 OpenAI 兼容接口，完成多轮对话。 2. 做一个「结构化抽取」小工具：输入一段 JD，按固定 JSON schema 抽出岗位名、要求技能、年限。 3. 对比不同 temperature / 提示写法在同一问题上的输出稳定性，记录差异。

验收标准 - 能独立跑通多轮对话与流式输出； - 输出能稳定解析为结构化数据，异常时有兜底； - 能解释上下文窗口、Token、温度分别影响什么。

阶段 2：RAG + 工具调用 + Agent 编排 + MCP（约 3–4 周）

目标：搭出一个带检索和工具调用的多步 Agent。

学习项 - RAG 全链路：文档解析 → 文本切分（按语义/长度/重叠）→ Embedding → 向量库写入 → 相似度检索 → Top-K 与阈值 → （可选）Rerank → 拼上下文 → 生成答案。 - Embedding 与向量：向量含义、余弦相似度、向量库选型（轻量 Chroma / 生产 Milvus）、召回质量评估。 - Function Calling：工具名/参数 schema 定义、模型决策是否调用、入参填充、执行结果回填、继续生成。 - Agent 编排：规划（任务拆解）→ 工具选择 → 观察结果 → 下一步；记忆（短期会话 / 长期检索）；循环终止条件。 - 框架与协议：LangChain 或 LlamaIndex 的链路组装；MCP 标准工具接口形态。 - 多模态：图片/语音接入方式与适用边界（了解即可）。

动手实验 1. 把一批 Markdown / PDF 文档入库，做语义检索问答，回答必须引用检索片段。 2. 给 Agent 接 2–3 个工具（如检索内部资料、查天气/时间、做计算），让模型自主选择调用。 3. 接一个 MCP 数据源或工具，跑通标准协议调用。

验收标准 - 能讲清 RAG 每一步为什么这么做、常见失效点（切分不当、召回不准、上下文污染）； - Agent 能根据问题自主选工具、回填结果并给出答案，有终止条件； - 知道框架与原生 SDK 各自适用场景。

阶段 3：服务化 + 部署 + 工程稳定性（约 2–3 周）

目标：把本地 Agent 变成可部署的后端服务。

学习项 - FastAPI：路由、请求/响应模型（Pydantic）、流式响应（SSE / streaming）、依赖注入、接口文档。 - 缓存与会话：Redis 存会话历史与检索缓存；数据库存长期记忆与反馈。 - 稳定性：超时、重试、限流、降级、日志、错误隔离；异步任务与阻塞调用分离。 - Docker：Dockerfile 编写、本地构建运行、环境变量与配置分离。

动手实验 1. 把阶段 2 的 Agent 包成 FastAPI 服务，提供对话接口与流式返回。 2. 接入 Redis 缓存会话与热点检索结果。 3. 写 Dockerfile，容器内跑通服务。

验收标准 - 服务能被其他端/脚本调用，流式输出正常； - 有基本的错误处理、超时与日志； - 镜像可本地构建启动。

阶段 4：项目沉淀与面试准备（持续）

  • 整理 1–2 个可演示项目（见第六节），写清架构图、数据流、技术选型理由、遇到的问题与取舍。
  • 简历措辞：从「移动端功能开发」转向「基于大模型的智能体应用落地」，突出 RAG、工具调用、服务化经验。
  • 面试准备：能白板讲清 RAG 链路、一次工具调用的完整时序、上下文/Token 成本控制、常见线上问题排查。

六、两个可落地项目（实操骨架）

项目 A：企业知识库 RAG 问答

定位：面向一批内部文档的语义问答，答案需可追溯到原文片段。

建议目录结构

│   ├── retrieve.py       # 向量检索 + 可选 Rerank

关键链路骨架（伪代码，可按所选厂商 SDK 替换）

# ingest.py：文档切分 -> Embedding -> 入库
def split(text, chunk_size=500, overlap=80):
    chunks = []
    for i in range(0, len(text), chunk_size - overlap):
        chunks.append(text[i:i + chunk_size])
    return chunks

def ingest(docs):
    for doc in docs:
        for chunk in split(doc.text):
            vec = embed(chunk)              # 调 Embedding 接口
            vector_store.add(doc_id=doc.id, text=chunk, vector=vec)

# retrieve.py：相似度检索 + Top-K 过滤
def retrieve(query, top_k=5):
    qvec = embed(query)
    hits = vector_store.search(qvec, top_k=top_k)
    return [h for h in hits if h.score > 0.75]

# answer.py：拼上下文 -> 生成，要求引用片段
def answer(question):
    ctx = retrieve(question)
    prompt = f"""
    仅依据下面的资料回答问题；资料不足就说明无法回答。
    资料：{ctx}
    问题：{question}
    """
    return llm.chat(prompt, stream=True)

自检点 - 召回不到相关片段时，模型不能编造； - 切分大小、重叠、Top-K、阈值可调，记录对效果的影响； - 答案标注引用来源文档与片段。

项目 B：工具调用 Agent

定位：模型自主判断是否调用工具、填充参数、回填结果继续回答。

工具 schema 示例

TOOLS = [
    {
        "name": "search_kb",
        "description": "检索企业内部知识库",
        "parameters": {
            "type": "object",
            "properties": {"query": {"type": "string", "description": "检索关键词"}},
            "required": ["query"],
        },
    },
    {
        "name": "get_time",
        "description": "获取当前时间",
        "parameters": {"type": "object", "properties": {}},
    },
]

def call_tool(name, args):
    if name == "search_kb":
        return retrieve(args["query"])
    if name == "get_time":
        return now().isoformat()
    raise ValueError(name)

多步循环骨架

def run_agent(question, max_steps=5):
    messages = [{"role": "user", "content": question}]
    for _ in range(max_steps):
        resp = llm.chat(messages, tools=TOOLS)
        if not resp.tool_calls:
            return resp.content
        for call in resp.tool_calls:
            result = call_tool(call.name, call.args)
            messages.append({"role": "tool", "content": str(result)})
    return "达到最大步数，任务未完成。"

自检点 - 工具参数解析失败时有重试或回退； - 有明确的最大步数与终止条件，避免死循环； - 工具执行异常不直接崩掉服务，转为可读错误返回。

七、学习资源选型原则

  • 优先官方文档与开源示例：所选 LLM 厂商的 API 文档、Embedding/向量库官方教程、框架官方 Quickstart；先跑通最小示例再扩功能。
  • 不绑定付费课程：路线以可执行项目为驱动，遇到概念缺口再定点查资料。
  • 代码可复现：每个实验都留在自己仓库，形成可展示的提交历史。
